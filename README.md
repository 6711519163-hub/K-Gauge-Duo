# Sport Dashboard — Honda / Yamaha K-Line ECU Gauge

มิเตอร์สปอร์ตสำหรับมอเตอร์ไซค์ อ่านข้อมูลสดจาก ECU ผ่านสาย **K-Line** (Honda Keihin / Yamaha) แล้วแสดงผลบนจอสัมผัส 4.3" พร้อมไฟเตือนรอบ (Shift Light) เสียงเตือน เลขไมล์/ทริป แผนที่ AFR แบบเรียนรู้เอง และอ่าน/ลบรหัสข้อผิดพลาด (DTC)

ระบบประกอบด้วย **2 บอร์ด** ทำงานร่วมกัน และมีเส้นทางสำรองในตัว:

| บอร์ด | ไฟล์หลัก | หน้าที่ |
|---|---|---|
| **Sender** (ติดตั้งใกล้ ECU) | `ecu_reader_c3__1.ino` | คุยกับ ECU ผ่าน K-Line, อ่านเซนเซอร์เกียร์/ความเร็วล้อ, ส่งข้อมูลไปจอด้วย ESP-NOW |
| **Display** (ติดหน้าปัด) | `display_receiver_s3.ino` + `*.h` | แสดงผล UI (LVGL), ไฟเตือนรอบ, เสียง, ตั้งค่า, เก็บไมล์/แผนที่ AFR ลงแฟลช และมี K-Line ในตัวไว้เป็นทางสำรอง |

> ⚠️ **ข้อควรระวังด้านความปลอดภัย:** โปรเจคนี้เป็นเครื่องมือแสดงผล/วินิจฉัยเท่านั้น ค่า Trim ในแผนที่ AFR เป็น "บันทึกของผู้ขับขี่" **ไม่ได้ส่งค่าไปแก้ ECU** ห้ามดูหน้าจอ/ตั้งค่าระหว่างขับขี่ และการต่อสายเข้า ECU ควรทำโดยผู้ที่เข้าใจระบบไฟของรถ

### ลำดับความสำคัญของแหล่งข้อมูล (ฝั่งจอ)

จอเลือกแหล่งข้อมูลทุกรอบใน `updateData()`:

1. **ESP-NOW** (`LINK_ESPNOW`) — ใช้เมื่อได้รับแพ็กเก็ตภายใน **2 วินาที**, `ecuConnected = true` และยี่ห้อตรงกับที่เลือก
2. **K-Line ในตัวจอ** (`LINK_KLINE`) — ใช้เมื่อข้อ 1 ใช้ไม่ได้ และ K-Line ของจอเชื่อมต่อได้
3. **ไม่มีข้อมูล** (`LINK_NONE`) — สถานะ `OFFLINE` / `CONNECTING`

> ถ้าต่อสาย K-Line ของ Sender และของจอเข้ากับ ECU **ตัวเดียวกันพร้อมกัน** ทั้งสองฝั่งจะพยายามเปิดการสื่อสารกับ ECU ชนกันได้ ให้ต่อฝั่งใดฝั่งหนึ่ง หรือทดสอบแยกก่อน (ดูหัวข้อ 14)

## 3. การเดินสายและวงจร

### 3.1 K-Line

```
 ECU K-Line ──────┬──────────────┐
                  │         ┌────┴─────┐      ESP32 TX ───► TXD
        (pull-up  │         │ L9637D / │      ESP32 RX ◄─── RXD
         ในตัว    │         │ MC33290  │      (ต้องมีวงจรแปลงระดับ 12 V ↔ 3.3 V)
         ECU/IC)  │         │ K-Line   │
                  │         │ transceiver
 GND ─────────────┴─────────┴──────────┘
```

- วงจรแปลงอย่าง **L9637D / MC33290 สะท้อนทุกไบต์ที่ส่ง (TX) กลับมาที่ RX** (Hardware Echo) — ซอฟต์แวร์จัดการด้วย "Echo Eraser" (ดูหัวข้อ 4.4)
- ห้ามต่อ GPIO ของ ESP32 เข้ากับ K-Line 12 V ตรง ๆ

### 3.2 ไฟเตือนรอบ WS2812B (14 ดวง: ข้างละ 7)

```
 ESP32 GPIO18 ──[330 Ω]──► DIN LED1 ─► … ─► LED14   (ทั้งหมด 14 ดวงต่ออนุกรม สายข้อมูลเดียว)
 5 V (จ่ายจากแหล่งจ่าย 5 V ที่เหมาะสม; 14 ดวงขาวเต็มกินราว ~1 A)
 GND แหล่งจ่าย ─── ต่อ GND ร่วมกับบอร์ด
 คาปาซิเตอร์ 470–1000 µF คร่อม 5 V/GND ใกล้ LED
```

- แนะนำ level shifter **74AHCT125 / 74HCT245** (3.3 V อาจใช้ได้กับสายสั้น แต่ไม่เสถียร)
- ลำดับสีบนสาย: **GRB** (WS2812B) — สร้างสัญญาณด้วย **RMT** (10 MHz, 100 ns/tick), T1H 0.8 µs / T0H 0.4 µs, 1 เฟรม ≈ 0.5 ms และส่งเฉพาะเมื่อเฟรมเปลี่ยน
- โครงสร้างโซ่: LED 0–6 = ข้างซ้าย, LED 7–13 = ข้างขวา; ตั้งค่า `ledRev` ได้ถ้าแถบขวาต่อกลับทิศ

### 3.3 เสียง (I²S)

I²S Standard (Philips) ส่งออกสเตอริโอ 16-bit ที่ **16 kHz** ไปยังแอมป์บนบอร์ด (BCLK 42 / WS 2 / DOUT 41) ใช้ไดรเวอร์ `driver/i2s_std.h` ของ ESP-IDF 5.x (Arduino core 3.x) — ไฟล์ตั้งชื่อ `driver_i2s.h` โดยเจตนา เพื่อไม่ชนกับ `driver/i2s.h` เดิมของ IDF

## 4. โปรโตคอล K-Line

ทั้ง Sender และ `driver_kline.h` ของจอใช้ชุดคำสั่งและตำแหน่งไบต์ **เดียวกัน** (UART 8N1)

### 4.1 Honda (Keihin) — 10400 bps

**Wake-up / Fast-init:** TX ค้าง HIGH ≥100 ms → **LOW 70 ms → HIGH 130 ms** แล้วเปิด UART ที่ 10400 bps

**เฟรม:** `0x02 | LEN | … | CHK` โดย `LEN` = ความยาวเฟรมทั้งหมด (รวมไบต์ `0x02` และ `CHK`), `CHK` = `(0x100 − Σbytes) & 0xFF` (two's complement ของผลรวมไบต์ก่อนหน้า)

| คำสั่ง | ไบต์ (HEX) | ใช้ทำอะไร |
|---|---|---|
| Wake-up | `FE 04 72 8C` | ปลุก ECU |
| Init | `72 05 00 F0 99` | เริ่มเซสชัน |
| Connect "TN" (เฉพาะ Sender) | `2C 54 4E 23` | ทางเลือกสำรองตอนเชื่อมต่อ |
| **Table 0x17** | `72 05 71 17 01` | RPM / TPS / อุณหภูมิ / แบตเตอรี่ / หัวฉีด / จุดระเบิด |
| **Table 0x20** | `72 05 71 20 F8` | O2 / AFR |
| ECM-ID | `72 05 71 00 18` | อ่านรหัส ECM (Sender เท่านั้น) |
| อ่าน DTC | `72 05 74 01 14` | `CHK` คำนวณอัตโนมัติ |
| ลบ DTC | `72 05 60 03 26` | `CHK` คำนวณอัตโนมัติ |

**ลำดับเชื่อมต่อ**
- Sender: `FE-wakeup` → `Init` → `TN` → `Init` → `T17` (ลองทีละขั้นจนกว่าจะได้เฟรมที่ checksum ถูก)
- Display (สำรอง): `FE-wakeup` → `Init` → `T17`
- ECU ถือว่าเชื่อมต่อสำเร็จเมื่อได้ **เฟรมที่ขึ้นต้น `0x02` และ checksum ถูกต้อง** หลังตัด Echo แล้วเท่านั้น

**รอบโพลล์ (Sender):** อ่าน **Table 0x17 จำนวน 10 ครั้ง : Table 0x20 จำนวน 1 ครั้ง** (วงจร 11 ขั้น) และส่งแพ็กเก็ตเข้าจอทันทีที่ได้ค่าใหม่

**การถอดรหัส Table 0x17** (index นับจากไบต์ `0x02` ของเฟรม = 0)

| Offset | ฟิลด์ | สูตร |
|---|---|---|
| `0x04–0x05` | RPM | `(b4 << 8) \| b5` (รอบตรง ๆ) |
| `0x06` | TPS (โวลต์) | `b6 × 5 / 256` |
| `0x07` | TPS (%) | `b7 × 0.5` |
| `0x09` | อุณหภูมิน้ำ °C | `b9 − 40` |
| `0x0E` | แบตเตอรี่ V | `b14 / 10` |
| `0x0F–0x10` | หัวฉีด ms | `((b15 << 8) \| b16) / 250` |
| `0x11` | มุมจุดระเบิด ° | `b17 / 2 − 64` |

(ต้องมีเฟรมยาวอย่างน้อย `0x13` ไบต์)

**Table 0x20:** `O2 (V) = b4 × 2.5 / 128`

**AFR (คำนวณฝั่งจอ)** จากแรงดัน O2 แบบเส้นตรงเป็นช่วง:
```
O2 ≤ 0.45 V :  AFR = 18.0 − (O2 / 0.45) × 3.3
O2 > 0.45 V :  AFR = 14.7 − ((O2 − 0.45) / 0.55) × 3.7
```

**ECM-ID (Sender):** อ่านไบต์ตั้งแต่ index 4 ถึงก่อน checksum แปลงเป็นสตริง HEX (สูงสุด 5 ครั้ง) — ฝั่ง Honda ของจอ K-Line ใช้ชื่อคงที่ `HONDA-KEIHIN`

**DTC Honda:** อ่านจาก payload ตำแหน่ง 3, 5, 7 เป็นคู่ `(main, sub)` (สูงสุด 3 รหัสจากเฟรมเดียว; ค่า `0x00`/`0xFF` ถือว่าว่าง) รองรับสูงสุด 12 รายการต่อแพ็กเก็ต

### 4.2 Yamaha — 15625 bps (สแกน 10400 bps ตามหลัง)

**Fast-init:** TX **HIGH > 300 ms (ใช้ 320 ms) → LOW 25 ms → HIGH 25 ms** แล้วเปิด UART — สแกน **15625 bps ก่อน** แล้วจึง **10400 bps** (ลองซ้ำแบนด์ละ 2 ครั้ง)

**ขั้นตอนเชื่อมต่อ:** ส่ง `0xFE` รอคำตอบ 200 ms; ถ้าเงียบ ส่ง poll `0x01` แล้วตรวจว่ามีเฟรมที่ใช้ได้

**สตรีมข้อมูล** (หลังส่ง `0x01` และตัด Echo; ไม่มี header/ความยาว) — ยืนยันจากการดักข้อมูลจริงบน **M-Slaz V2**

```
 ไบต์: [0] RPM  [1] VSS  [2] ERR  [3] TEMP  [4] CHK
 CHK = (RPM + VSS + ERR + TEMP) & 0xFF
```

| ฟิลด์ | การแปลง | สถานะ |
|---|---|---|
| RPM | `raw × 50` | ยืนยันแล้ว |
| TEMP °C | `raw − 30` | ⚠️ **PROVISIONAL** (ตัวเลือกอื่น: `raw / 2`) |
| VSS | ไม่ใช้ (`KL_YAM_USE_ECU_SPEED = 0`) ใช้ความเร็วจากเซนเซอร์ล้อ GPIO13 แทน | ปรับได้ด้วย `*_USE_ECU_SPEED` / `*_SPEED_SCALE` |
| ERR | bit7 = มีรหัสผิดพลาด, `ERR & 0x7F` = รหัส | ใช้เป็น DTC |
| TPS, แบตฯ, หัวฉีด, จุดระเบิด, O2 | **ไม่มีในสตรีม Yamaha** — ตั้งค่า 0 | — |

`kl_yam_find_frame()` สแกนหาตำแหน่ง 5 ไบต์ที่ checksum ตรงและไม่ใช่ศูนย์ทั้งหมด (ค้นย้อนจากท้ายบัฟเฟอร์) ECM-ID ของ Yamaha คือ `YAMAHA-ECU` ทันที **ไม่เคยส่งคำสั่ง ECM-ID แบบ Honda**

> ลบ DTC ของ Yamaha: **ยังไม่ได้ทำ** (ส่งผลลัพธ์ว่างกลับไปเฉยๆ) และอ่าน DTC ทำได้เฉพาะตอนเครื่อง **ดับ** (`rpm == 0`)

### 4.3 กำหนดเวลาโปรโตคอล (ค่าหลักในโค้ด)

| พารามิเตอร์ | Sender | Display K-Line |
|---|---|---|
| Honda baud / Yamaha baud | 10400 / 15625 | 10400 / 15625 |
| Timeout T17 / T20 | 100 / 100 ms | 100 / 100 ms |
| Timeout DTC | 300 ms | — |
| ช่องว่างจบเฟรม | 2 ms | 6 ms (Yamaha read-quiet) |
| จำนวนโพลล์พลาดก่อนตัดการเชื่อมต่อ | 5 ครั้งติดกัน | 5 ครั้งติดกัน (`KL_FAIL_LIMIT`) |
| พักก่อนสแกนใหม่ | 2500 ms + retry 2000 ms | 1500 ms |
| รอบโพลล์ถัดไป | ทันที (gap 0 ms) | 50 ms |

### 4.4 Hardware Echo Eraser

ทรานซีฟเวอร์ K-Line สะท้อนไบต์ที่ส่งกลับมายัง RX ถ้าไม่ตัดออก ไบต์ที่สะท้อนจะถูกตีความเป็นคำตอบของ ECU (เช่น `0xFE` ถูกเข้าใจผิดว่า Yamaha ตอบ)

- หลังส่งเสร็จ (`flush()`), ตรวจ RX ด้วย `peek()` — **ทิ้งเฉพาะไบต์ที่ตรงกับไบต์ที่ส่งตามลำดับ** ไบต์จริงของ ECU จะไม่ถูกกลืน
- หน้าต่างเวลา = `n × 10 bit / baud + 4 ms`
- ถ้าไม่พบ Echo เลย **3 ครั้งติดกัน** และไม่เคยเห็น Echo มาก่อน ระบบจะปิดตัวเองอัตโนมัติ (รองรับทรานซีฟเวอร์ที่ไม่มี Echo)
- ฝั่ง Sender สำหรับ Honda ใช้วิธี "รองรับทั้งมี Echo (offset = ความยาวคำสั่ง) และไม่มี Echo (offset = 0)" เมื่อตรวจเฟรม

## 5. โปรโตคอล ESP-NOW (Sender ↔ Display)

- **Wi-Fi channel: 1** (`ESPNOW_WIFI_CHANNEL`) ทั้งสองฝั่งตั้งช่องเดียวกัน
- **Broadcast** ไปที่ `FF:FF:FF:FF:FF:FF`, **ไม่เข้ารหัส** (`encrypt = false`)
- Sender ลดกำลังส่งเป็น `WIFI_POWER_11dBm`
- โครงสร้างทั้งหมดเป็น `__attribute__((packed))` อยู่ใน `shared_data_struct.h`
  > **สำคัญ:** ไฟล์นี้ต้อง **เหมือนกันทุกไบต์** ในสเก็ตช์ทั้งสอง (`shared_data_struct_1.h` ที่อัปโหลดมา ตรวจแล้ว **เหมือนกันทุกบรรทัด**)

### 5.1 การแยกแพ็กเก็ต

ตัวรับแยกประเภทด้วย **ความยาวแพ็กเก็ต** แล้วค่อยตรวจ `packetType` — ขนาดทุกแบบ **ต้องไม่ซ้ำกัน**:

| แพ็กเก็ต | `packetType` | ขนาด (ไบต์) | ทิศทาง | ความถี่ |
|---|---|---|---|---|
| `GaugeDataPacket` | `0x01` | **44** | Sender → Display | ~60 Hz (ทุก 16 ms) + ทุกครั้งที่ได้ค่า ECU ใหม่ + เมื่อเกียร์เปลี่ยน |
| `HeartbeatPacket` | `0x02` | **5** | Display → Sender | 1 Hz |
| `DtcDataPacket` | `0x03` | **27** | Sender → Display | ตามคำขอ (busy → ผลลัพธ์) |
| `DtcCommandPacket` | `0x04` | **2** | Display → Sender | ตามคำขอ |
| `EcmIdPacket` | `0x05` | **22** | Sender → Display | ทุก 2 s + เมื่อเปลี่ยนสถานะ |
| `EcuSelectPacket` | `0x06` | **4** | Display → Sender | ทุก 2 s (เมื่อเลือกยี่ห้อแล้ว) + เมื่อเปลี่ยนยี่ห้อ |

> ⚠️ หากเพิ่มแพ็กเก็ตใหม่ **ห้ามให้ `sizeof` ซ้ำกับตารางข้างต้น** มิฉะนั้นตัวรับจะแยกประเภทผิด

| Offset | ชนิด | ฟิลด์ | หมายเหตุ |

| 2 | `uint16` | `rpm` | รอบ/นาที |
| 4 | `float` | `speedKmh` | ความเร็วล้อดิบ (ก่อนปรับเทียบ) |
| 8 | `float` | `tps` | % |
| 12 | `float` | `tpsVolt` | V |
| 16 | `int16` | `tempC` | °C |
| 18 | `float` | `batteryV` | V |
| 22 | `float` | `injectorMs` | ms |
| 26 | `float` | `ignitionDeg` | องศา |
| 30 | `float` | `o2Volt` | V |
| 34 | `uint8` | `gear` | 0 = N, 1–4, 255 = ไม่ทราบ |
| 35 | `bool` | `ecuConnected` | |
| 36 | `bool` | `t17Ok` | อ่าน Table 0x17 สำเร็จ |
| 37 | `bool` | `t20Ok` | อ่าน Table 0x20 สำเร็จ |

### 5.3 แพ็กเก็ตอื่น

```c
HeartbeatPacket   { uint8 packetType=0x02; uint32 seq; }                       // 5 B
DtcItem           { uint8 mainCode; uint8 subCode; }
DtcDataPacket     { uint8 packetType=0x03; uint8 count; DtcItem items[12]; bool busy; }   // 27 B
DtcCommandPacket  { uint8 packetType=0x04; uint8 cmd; }                        // cmd: 0x01 = อ่าน, 0x02 = ลบ
EcmIdPacket       { uint8 packetType=0x05; bool valid; char text[20]; }        // สตริง NUL-terminated
EcuSelectPacket   { uint8 packetType=0x06; uint8 brand; uint8 chk; uint8 magic; }
                    // brand: 0 = ไม่ได้เลือก (สแกนทั้งคู่), 1 = Honda, 2 = Yamaha
                    // chk   = brand ^ 0xA5
                    // magic = 0x5A
```

## 6. ความเร็วล้อและเกียร์

### 6.1 ความเร็วล้อ (Sender, GPIO13)

| ค่า | ตั้งไว้ | ความหมาย |
|---|---|---|
| `SPEED_PULSES_PER_REV` | 2 | พัลส์ต่อรอบล้อ |
| `WHEEL_CIRCUMFERENCE_M` | 1.82 m | เส้นรอบวงล้อ (**ต้องปรับให้ตรงกับรถ**) |
| `SPEED_MIN_PULSE_US` | 2500 µs | ตัดสัญญาณรบกวน/เด้ง (debounce) |
| `SPEED_TIMEOUT_US` | 2 s | ไม่มีพัลส์เกินนี้ = ความเร็ว 0 |

```
km/h = ( (WHEEL_CIRCUMFERENCE_M / PULSES_PER_REV) / period_s ) × 3.6      (จำกัดสูงสุด 300)
period = ค่าเฉลี่ยเลื่อน (3 ส่วนเก่า : 1 ส่วนใหม่)
```

คำนวณทุก 30 ms ด้วย ISR (`IRAM_ATTR`) + critical section ฝั่งจอสามารถ **ปรับเทียบความเร็ว** ได้ในโหมดแอดมิน (50–150 %) โดยป้อนความเร็วจริงจากอุปกรณ์อ้างอิง

### 6.2 เกียร์ (Sender, GPIO3–7)

อ่านสวิตช์เกียร์ **N, 1, 2, 3, 4** (Active HIGH) พร้อม **debounce 30 ms** ก่อนส่งแพ็กเก็ตทันที — ค่า `255` = ไม่มีสวิตช์ใดทำงาน (ระหว่างเกียร์/ไม่ทราบ)

> UI และการตั้งค่าเตือนรอบรองรับ **6 เกียร์** แต่ฮาร์ดแวร์ฝั่ง Sender อ่านได้ถึง **เกียร์ 4** เท่านั้น เมื่อเกียร์ไม่ทราบ ระบบจะใช้ค่าเตือนรอบแบบ "ค่าเดียว" แทน

## 7. สถาปัตยกรรมซอฟต์แวร์ของจอแสดงผล

### 7.1 งาน (Tasks) และคอร์

| งาน | คอร์ | Priority | Stack | หน้าที่ |
|---|---|---|---|---|
| `TaskLVGL` | 1 | 3 | 8192 | `updateData()` → `uiUpdate()` → `lv_timer_handler()` (ถือ `xGuiMutex`) |
| `loop()` (Arduino) | 1 | — | — | Heartbeat, ECU-Select, ไฟเตือนรอบ (ทุก 20 ms) |

| `audio` | 0 | 5 | 4096 | สังเคราะห์เสียง I²S |

- **Event-driven wake-up:** callback ESP-NOW เรียก `xTaskNotifyGive()` ปลุก `TaskLVGL` ทันทีที่ข้อมูลมาถึง (รอสูงสุด 8 ms)
- ข้อมูลจาก ESP-NOW แลกเปลี่ยนผ่านตัวแปร `volatile` + `portMUX` critical section
- **ห้ามสร้าง/ลบวิดเจ็ตใน event callback** — UI ขอผ่านแฟล็ก `g_rebuildUi` แล้วให้ `TaskLVGL` สร้างใหม่ (`uiBuildAll()`)

### 7.2 การแสดงผล LVGL 8.3.11

- ความละเอียด **480×272**, สี **16-bit** (`LV_COLOR_16_SWAP 0`), หมุนจอ `setRotation(2)`
- **Double buffer** แบบ DMA ใน SRAM ภายใน ขนาด **40 บรรทัด** (480×40 พิกเซล) ×2 (ถ้าจองไม่ได้จะถอยเป็นบัฟเฟอร์เดียว)
- `refr_timer` = **8 ms** (~125 Hz เพดาน), อ่านทัช 20 ms, long-press 700 ms
- หน่วยความจำ LVGL ใช้ `malloc/free` ของระบบ (`LV_MEM_CUSTOM 1`), tick = `millis()`
- กฎ UI เพื่อความเร็ว: ใช้เฉพาะสี่เหลี่ยมทึบ + ข้อความ และ **ตั้งค่า widget ต่อเมื่อค่าเปลี่ยนจริง** (style setter ของ LVGL จะวาดซ้ำแม้ค่าเดิม)
- **ธีม:** Dark (พื้นดำ เส้นกรอบ สีสด) / Light, **2 ภาษา:** อังกฤษ / ไทย — ทุกข้อความอยู่ในตารางสตริงเดียว (`STR_LIST` ใน `ui_core.h`)
- **ฟอนต์ไทย:** `font_thai_12/15/18` (4 bpp) ทำจาก Loma (TLWG) — ฟอนต์ Latin ใช้ Montserrat 10–48 จาก LVGL

| 4 | **FUEL MAP** | แผนที่ AFR เรียนรู้เอง 3 มุมมอง |

### 8.2 เลือกยี่ห้อ ECU

หน้าแรกเปิดมาให้เลือก **Honda / Yamaha** (จำค่าไว้แม้ปิดเครื่อง) — เมื่อเปลี่ยนยี่ห้อ จอจะ: บันทึกค่า, สั่ง K-Line ภายในสแกนใหม่, ส่ง `EcuSelectPacket` ให้ Sender (Sender บันทึกลง NVS ด้วย), ล้างข้อมูลสดและสถานะ DTC, และรีเซ็ต ECM-ID

### 8.3 เตือนรอบเกิน (Over-rev)

- **โหมดจำกัดรอบ:** แบบ "ค่าเดียว" หรือ "ตามเกียร์" (เกียร์ 1–6, N/ไม่ทราบ → ใช้ค่าเดียว)
- ค่าเริ่มต้น: ค่าเดียว 9000 rpm; ตามเกียร์ 6000/7500/8500/9000/9500/9800
- เปิดเตือนเมื่อ `rpm ≥ limit` และปิดเมื่อ `rpm + 200 < limit` (**Hysteresis 200 rpm** กันกะพริบ)
- ทำงานเฉพาะเมื่อ **Sport mode เปิด**; มีปุ่มทดสอบ (3 s)
- ผลลัพธ์: ภาพกะพริบเต็มจอ + เสียงเตือน + ไฟ LED กะพริบ

### 8.6 เลขไมล์และทริป

- ODO + TRIP A + TRIP B, สะสมจากความเร็วที่ **ปรับเทียบแล้ว** × เวลา
- ไม่นับเมื่อข้อมูลขาดช่วง (>2 s), ความเร็ว ≤0.5 หรือ >300 km/h
- บันทึกลงแฟลชทุกครั้งที่สะสมครบ **0.5 กม.**
- รีเซ็ตทริปด้วยการกดปุ่มวงกลมค้าง; แอดมินตั้งค่า ODO ได้

### 8.7 ระดับการเตือนค่า (สีไทล์)

ระดับ: `0` ปกติ · `1` เตือน · `2` อันตราย · `3` ต่ำ/เย็น

| ค่า | เตือน (1) | อันตราย (2) | ต่ำ (3) |
|---|---|---|---|
| ความเร็ว | ≥ 90 km/h | ≥ 110 km/h | — |
| อุณหภูมิน้ำ | ≥ 95 °C | ≥ 105 °C | < 50 °C |
| แบตเตอรี่ | < 12.0 V หรือ ≥ 14.8 V | < 11.5 V หรือ ≥ 15.2 V | — |
| AFR | ≥ 15.5 หรือ < 11.5 | ≥ 16.5 | — |
| หัวฉีด | ≥ 10 ms | — | — |
| จุดระเบิด | > 45° หรือ < 0° | — | — |

โซนสี RPM: เขียว < 60 % · เหลือง 60–90 % · แดง ≥ 90 % ของ `maxRpm` (ตั้งได้ 6000–16000)

### 8.8 แผนที่ AFR เรียนรู้เอง (`fuel_map.h`)

เรียนรู้ AFR เฉลี่ยจาก O2 **เฉพาะ Honda** (Yamaha ไม่มีข้อมูล O2) พร้อมกัน 2 แผนที่ขนาด 5×5:

| แผนที่ | แถว | คอลัมน์ |
|---|---|---|
| `rt` | RPM: <2500 / <4500 / <6500 / <8500 / ≥8500 | TPS: <10 / <30 / <50 / <70 / ≥70 % |
| `sg` | ความเร็ว: ≤20 / ≤55 / ≤90 / ≤125 / >125 | เกียร์ G1 / G2 / G3 / G4 / G5–6 |

- **เงื่อนไขเรียนรู้:** เปิด Auto-tune, AFR อยู่ในช่วง 9–19, rpm ≥ 1000, (โหมด Warm-only) น้ำ ≥ **75 °C**, สุ่มทุก 100 ms
- **การเฉลี่ย:** 30 ตัวอย่างแรกเฉลี่ยตรง ๆ จากนั้นใช้ตัวกรอง EMA (α = 0.03)
- **เป้าหมาย AFR (ค่าเริ่มต้น):** ตาม TPS 14.7 → 12.9; ตามความเร็ว 14.7 → 13.0 (เข้มขึ้นเมื่อโหลดสูง)
- **การจัดระดับ:** เทียบ `AFR − เป้า` → ≤ −0.7 **RICH** · < 0.35 **OK** · < 0.8 **S-LEAN** · มากกว่านั้น **LEAN** (ต้องมี ≥3 ตัวอย่างถึงแสดง)
- **ค่าชดเชย (trim)** −50…+50 % เป็นเพียงโน้ต/ข้อเสนอแนะ **ไม่ส่งเข้า ECU**; มุมมอง AFR / TRIM %; โหมด Advisor (เกียร์ + ความเร็ว)
- บันทึกลงแฟลช **เมื่อรถหยุด >5 วินาที** เท่านั้น (การเขียนแฟลชทำให้จอค้างชั่วขณะ)
- **ประหยัดน้ำมัน (km/L):** คำนวณจากเวลาหัวฉีด — ตั้ง `injCc` (cc/min) และจำนวนสูบ (1–4); `injCc = 0` = ซ่อนค่า
  ```
  L/h = (injCc/60) × (injMs/1000) × (rpm/120) × cyl × 3.6     (4 จังหวะ: หัวฉีดยิง 1 ครั้งต่อ 2 รอบเพลา)
  ```

### 8.9 โหมดแอดมิน

เข้าด้วย **กดค้าง 6 วินาที** → ใส่ **PIN 6 หลัก** (ค่าเริ่มต้นกำหนดใน `app_logic.h` ที่ `ADMIN_PIN` — **ควรเปลี่ยนก่อนใช้งานจริงและไม่ควรเผยแพร่ใน repo สาธารณะ**) ออกเองอัตโนมัติเมื่อไม่มีการสัมผัส **60 วินาที**

5 แท็บ: **General** (ODO, ปรับเทียบความเร็ว, ภาษา/ธีม) · **RPM alert** (maxRpm, โหมดจำกัดรอบ, พรีเซ็ต, ปุ่มทดสอบ) · **LED** · **Clock** · **Fuel** (ขนาดหัวฉีด/จำนวนสูบ) — ปุ่ม **Save** บันทึก, **Exit** โหลดค่าเดิมคืน

## 9. ระบบป้องกันและความทนทาน

### 9.1 ด้านการสื่อสาร

| ระบบ | รายละเอียด |
|---|---|
| **Echo Eraser** | ตัด Echo ของทรานซีฟเวอร์ K-Line ด้วย `peek()` ทีละไบต์ + ปิดตัวเองเมื่อไม่มี Echo |
| **ตรวจ Checksum** | Honda: ตรวจ `0x02 + LEN + CHK` ทุกเฟรม; Yamaha: ตรวจผลรวม 4 ไบต์ + ไม่รับเฟรมศูนย์ล้วน |
| **ตรวจความยาวเฟรม** | ปฏิเสธเฟรมที่ `LEN < 4` หรือเกินบัฟเฟอร์ |
| **Link-loss detection** | โพลล์พลาด 5 ครั้งติดกัน → ตัดลิงก์, ล้างข้อมูล, พักแล้วสแกนใหม่ |
| **ล้างข้อมูลทุกครั้งที่เชื่อมต่อใหม่** | ค่าของ Honda ไม่รั่วเข้าเซสชัน Yamaha และกลับกัน |
| **กรองตามยี่ห้อ** | สแกนเฉพาะยี่ห้อที่เลือก; จอไม่รับข้อมูลที่ `ecuType` ไม่ตรงยี่ห้อ |
| **Failover แหล่งข้อมูล** | ESP-NOW หลัก → K-Line ในจอ สำรอง (ESP-NOW ขาดเกิน 2 s จะสลับเอง) |
| **Heartbeat** | จอส่งทุก 1 s; Sender แสดงสถานะ (เกิน 3 s = จอหาย) |
| **ป้องกันคำสั่งเลือกยี่ห้อผิด** | `chk = brand ^ 0xA5` + `magic = 0x5A` + ตรวจค่า brand ที่ถูกต้อง |
| **ตรวจขนาด+ชนิดแพ็กเก็ต** | แยกด้วย `len` แล้วตรวจ `packetType` ซ้ำก่อนรับ |
| **DTC ปลอดภัย** | อ่าน/ลบได้เฉพาะ **ECU เชื่อมต่อและเครื่องดับ (rpm = 0)**; ถ้าเครื่องติดจะตอบรายการว่าง และ UI แสดง "เครื่องยังติด" |

### 9.2 ด้านฮาร์ดแวร์/เซนเซอร์

- **ISR ความเร็วล้อ** กรองพัลส์ที่ถี่กว่า 2.5 ms, timeout 2 s, จำกัด 300 km/h, ใช้ `portMUX`
- **Debounce เกียร์ 30 ms**
- **GT911:** ถ้าอ่าน I²C พลาด (ได้ `0xFF`) จำนวนจุดสัมผัสจะถูกบังคับเป็น 0 กัน index เกิน `points[5]`
- **LED:** ส่งเฟรมเฉพาะเมื่อเปลี่ยน; ปิดระบบได้ด้วย `WS2812_PIN = -1`
- **เสียง:** DMA `auto_clear` (เงียบเมื่อบัฟเฟอร์ว่าง), ramp กัน pop
- **อุณหภูมิ ≥105 °C** → เสียงเตือนความร้อนอัตโนมัติ

### 9.3 ด้านข้อมูลและแฟลช

- `settingsClamp()` บีบค่าที่อ่านจากแฟลชให้อยู่ในช่วงปลอดภัยเสมอ (ภาษา, ODO, ปรับเทียบ 50–150 %, maxRpm, ค่ารอบเตือน, ค่า LED ฯลฯ)
- `fuelLoad()` ตรวจ **เวอร์ชันโครงสร้าง** (`0xF0E10001`) และ **รีเซ็ตทุกเซลล์ที่ค่าไม่สมเหตุสมผล**
- บันทึก ODO เป็นช่วง (ทุก 0.5 กม.) และบันทึกแผนที่เฉพาะตอนรถหยุด — ลดการเขียนแฟลชและกันจอค้างขณะขับ
- ODO ข้ามช่วงข้อมูลขาด (>2 s) ไม่ "เดาระยะ"
- PIN 6 หลัก, กดค้าง 6 วินาที, หมดเวลาอัตโนมัติ 60 วินาที

### 9.4 ข้อจำกัดด้านความปลอดภัยที่ควรรู้

- ESP-NOW เป็น **broadcast ไม่เข้ารหัส** — ใครอยู่ในระยะส่งแพ็กเก็ตรูปแบบเดียวกันได้ `chk/magic` ของ ECU-Select เป็นเพียงตัวกันส่งผิดพลาด **ไม่ใช่การยืนยันตัวตน**
- PIN แอดมินถูกฝังในซอร์ส ควรเปลี่ยนและตั้ง `SHOW_PIN_HINT 0` (ค่าเริ่มต้นเป็น 0 แล้ว)

## 14. ข้อจำกัดและสิ่งที่ควรตรวจสอบ

จากการอ่านโค้ด สิ่งที่ควรยืนยัน/ระวัง:

1. **ชนิดบอร์ด Sender:** ชื่อไฟล์ `ecu_reader_c3` แต่คอมเมนต์ระบุ NeoPixel ที่ GPIO48 ซึ่งมีเฉพาะ ESP32-S3 — โปรดยืนยันบอร์ดจริงก่อนเลือก Board ในการคอมไพล์
2. **เกียร์ 5–6:** Sender อ่านสวิตช์ได้ถึงเกียร์ 4 แต่ UI/ตั้งค่ารองรับ 6 เกียร์ (เกียร์ที่ไม่ทราบจะใช้ค่าเตือนรอบแบบเดี่ยว) และแผนที่ AFR แบบ Speed×Gear รวมเกียร์ 5–6 ไว้คอลัมน์เดียว
3. **K-Line สองทาง:** ทั้ง Sender และจอมี K-Line ของตัวเอง — ถ้าต่อเข้าสาย ECU เส้นเดียวกันพร้อมกันอาจชนกัน ควรใช้ฝั่งใดฝั่งหนึ่งเป็นหลัก
4. **Yamaha:** ค่าอุณหภูมิ (`raw − 30`) เป็น **PROVISIONAL**; ไม่มี TPS/แบตฯ/หัวฉีด/จุดระเบิด/O2; ลบ DTC ยังไม่รองรับ; ความเร็วใช้เซนเซอร์ล้อ (ปิดการใช้ VSS จาก ECU ไว้)
5. **Honda DTC:** ถอดรหัสจากตำแหน่ง payload คงที่ (สูงสุด 3 รหัส/เฟรม) ควรตรวจกับรถจริงก่อนเชื่อผลลัพธ์
6. **ความปลอดภัยไร้สาย:** ESP-NOW ไม่เข้ารหัส + PIN ฝังในซอร์ส (หัวข้อ 9.4)
7. **การเขียนแฟลช:** ODO บันทึกทุก 0.5 กม. (ระหว่างขับ) อาจทำให้จอสะดุดชั่วขณะ และมีผลต่ออายุแฟลชในระยะยาว
8. **ความแม่นยำ AFR:** สูตรแปลง O2→AFR เป็นการประมาณแบบเส้นตรงจากแรงดัน ใช้ดูแนวโน้ม ไม่ใช่ค่าวัดมาตรฐานของ wideband
9. **เส้นรอบวงล้อ:** ค่า `WHEEL_CIRCUMFERENCE_M = 1.82` และ `SPEED_PULSES_PER_REV = 2` ต้องปรับให้ตรงกับรถ แล้วใช้การปรับเทียบบนจอช่วยละเอียดอีกชั้น
